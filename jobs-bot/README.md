# OOOPS Jobs — Telegram дайджест заказов

Отдельный сервис внутри репозитория OOOPS. **Не меняет сайт студии.**
Каждый день GitHub Actions читает **только публичные** Telegram-каналы,
отбирает проекты под компетенции OOOPS и публикует до 8 вакансий/заказов
в рабочий Telegram-чат.

## Направления
- Автоматизация, интеграции, API, Telegram-боты, парсеры, CRM
- Разработка сайтов, Frontend/Backend, Python, веб-сервисы, MVP, Mini Apps
- UX/UI, аудит интерфейсов и UX-исследования
- Презентации, графика, инфографика
- Брендинг и айдентика
- Контент, SMM, монтаж и видео
- Аналитика данных и дашборды

Это фильтр по ключевым словам и контексту (эвристика); здесь **нет обещания,
что каждый заказ проверен человеком или оценён нейросетью**. Каждая ссылка
ведёт на исходное объявление. Мы не читаем закрытые чаты и не отправляем
отклики без явного действия человека.

## Посмотреть предварительную подборку без токена
В GitHub → Actions → OOOPS Jobs → Run workflow выберите **mode = preview**.\nРабочая подборка появится в логах, без отправки в Telegram.\nЭто также проверяет доступность публичных каналов с сервера GitHub.\n\n## Первичная настройка (один раз)

1. В Telegram откройте официального **@BotFather**, создайте бота
   командой /newbot и сохраните выданный токен **не в переписке**.
2. Добавьте созданного бота в рабочую Telegram-группу OOOPS.
   Отправьте в группе команду /start или /chatid, адресованную боту.
3. В GitHub откройте репозиторий ulko31/luna →
   **Settings → Secrets and variables → Actions → New repository secret**.
   Создайте секрет **OOOPS_JOBS_BOT_TOKEN** со значением токена.
4. Чтобы безопасно узнать ID группы: откройте
   **Actions → OOOPS Jobs — ежедневные заказы → Run workflow**,
   установите **mode = discover**. После выполнения найдите в логах
   строку `group: -100...`. Скрипт не выводит токен и сообщения.
5. Создайте второй секрет **OOOPS_JOBS_CHAT_ID** со значением этого ID.
6. Снова запустите **Run workflow**, оставив **mode = send**.
   В чате должна появиться тестовая подборка (или сообщение,
   что сегодня подходящих объявлений нет).
7. Автоматический дайджест: **09:17 по Москве ежедневно**.
   GitHub Actions выполняет запланированные задания приблизительно,
   иногда с задержками. Можно изменить cron в файле workflow.

### Почему не нужно присылать токен сюда
Токен даёт контроль над ботом. Он должен быть только в GitHub Actions secrets.
Если токен случайно утечёт, его можно перевыпустить в BotFather.

## Отправка в конкретную тему Telegram

Если бот отправляет дайджест в общую тему, можно направить его
в тему **«клиенты и переговоры»** без изменения общего ID группы.

1. Откройте именно тему «клиенты и переговоры» в группе OOOPS.
2. Отправьте команду `/chatid@ooops_new_order_bot` **без пробелов**
   (после /chatid укажите username вашего созданного бота).
3. GitHub → Actions → OOOPS Jobs → Run workflow → **mode: discover**.
   В логах шага Discover найдите строку `topic: group=-100… | thread=123`.
   Сверьте `group` с уже настроенным значением `OOOPS_JOBS_CHAT_ID`.
4. GitHub → Settings → Secrets and variables → Actions → New repository secret:
   имя `OOOPS_JOBS_THREAD_ID`, значение — **только число после thread=**.
5. Запустите **mode: send**. Дайджест должен появиться внутри выбранной темы.

Если в логах только `No topic thread found yet`, проверьте, что команда
отправлена **внутри темы** и адресована боту; затем повторите discover.

Секрет `OOOPS_JOBS_THREAD_ID` необязателен: без него сообщение
продолжит приходить в общую тему. Не меняйте уже работающие токен и chat ID.

## Dprofile — источник заказов

Добавлен официальный публичный Telegram-канал [Dprofile. Заказы](https://t.me/dprofilefreelance).
Он включён в обычный ежедневный мониторинг вместе с остальными источниками,
без дополнительных токенов. Dprofile публикует в нём подборки объявлений
с площадки, но **не гарантирует дублирование каждого заказа сразу**.

Если пост содержит прямую ссылку вида `https://dprofile.ru/job/...`,
бот сохраняет её, чтобы открывался оригинальный заказ. Иначе оставляет
ссылку на сообщение официального канала.

**Ограничение:** это подключение официального канала Dprofile, а не
авторизованный API и не полный каталог всех заказов сайта. Для полного
мониторинга каталога потребуется отдельный надёжный источник данных;
не пытайтесь обходить ограничения доступа площадки.

Проверить: GitHub Actions → OOOPS Jobs → Run workflow → `preview`.
В логах должен встретиться источник `dprofilefreelance` с числом
доступных публичных сообщений. Не каждый доступный пост обязан пройти
фильтры свежести и релевантности.

## Источники и отбор
По умолчанию:
`zakaz_design, GetClient, FreeVacanciesIT, frilans, Koteyka_Freelancer,
vacancysmm, designer_jobs, uxui_jobs, jobgeeks, fordev, python_jobs,\ndprofilefreelance`.

Для работы берутся публичные страницы `t.me/s/<channel>`.
Если Telegram блокирует просмотр источника, бот пропускает его и
фиксирует проблему в логах. Некоторые каналы могут быть недоступны
для этого метода. Даты публикаций старше 48 часов не попадают в подборку.
Ранжирование учитывает соответствие услугам OOOPS, признаки оплаты и
проектный формат. Прямые дубли по ссылке удаляются, похожие сообщения
из разных каналов могут повторяться.

Не выбираются очевидная самореклама, офисные вакансии и подозрительные
предложения со вступительными взносами. Это не полноценная проверка
работодателя: команда обязана самостоятельно проверять условия.

## Подготовленные отклики

В ежедневной подборке у каждого объявления появляются кнопки:

- **«Отклик N»** — если в объявлении найден прямой Telegram-контакт,
  открывает чат от вашего личного аккаунта и заранее вставляет короткий
  персонализированный черновик в поле ввода. Сообщение не отправляется само.
- **«Текст N»** — копирует тот же черновик для Dprofile, формы, email или
  объявления без прямого Telegram-контакта.
- **«Объявление N»** — открывает исходную страницу, когда прямой контакт
  безопасно определить не удалось.

Черновик содержит направление задачи и ссылку на портфолио OOOPS:
https://ooops-portfolio.vercel.app/. Перед
отправкой обязательно проверить имя, условия, бюджет, актуальность и подобрать
наиболее релевантный кейс. Бот не входит в пользовательский Telegram-аккаунт,
не обходит ограничения площадок и не рассылает сообщения автоматически.

## Проверка локально
Node.js >=20:
```bash
cd jobs-bot
npm test
DRY_RUN=1 node digest.mjs
```

Для добавления новых источников отредактируйте массив CHANNELS
в `digest.mjs`. Учитывайте правила доступа каждого ресурса.

## Качество черновиков отклика

- Основное направление определяется по заголовку, хештегу и формулировке задачи, а не по случайному слову в описании.
- Черновик предлагает конкретное решение по типу задачи и всегда требует ручного подтверждения отправки.
- Самореклама исполнителей, лид-магниты, подозрительные условия и неоплачиваемые проекты исключаются.
- После отправки ID Telegram-сообщений записываются в workflow logs для последующего редактирования.
